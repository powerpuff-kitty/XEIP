# Historical lifecycle checkpoints

Status: local capture and validation verified; a dependency of complete control recovery.

The `xeip.lifecycle-checkpoint/1` record preserves organization, public runtime configuration, initial public authority configuration, `initializing` or `initialized` phase, the original source checksum, and a digest covering all fields including phase and organization. Initial authority is setup intent, not necessarily the current authority configuration. Runtime preserves target endpoint/revision/recipient/tool and identity settings, optional trust-feed configuration and the normalized recovery binding/endpoint. Introspection, MCP, trust-feed and recovery credentials are excluded and must be provisioned separately during an eventual restore.

Offline validation uses existing trust, authority, MCP, feed and recovery rules without issuing network requests. It verifies the exact public field sets, expected organization, canonical configuration content, recovery genesis and scope, initial policy-to-target correspondence, original checksum and record digest. Existing limits remain: initial authority at most 1 MiB, combined runtime plus initial authority at most 2 MiB. Hashes detect corruption; they do not authenticate provenance or establish freshness against whole-history rollback.

Service capture is unavailable on uninitialized, failed or closed state and conflicts while initialization, an owner mutation, a trust poll or another capture is pending. It holds the control-operation guard while synchronizing storage, rechecks schema and exact intent after synchronization, and preserves the original lifecycle phase. Storage faults or unexpected state changes quarantine the service. A freshly reopened interrupted initialization can be captured without completing or resetting it. Capture does not include a consistent action/control cut, an independent journal receipt or permission to activate restored state.

Injected recovery settings must match the service organization before bootstrap can write anything. Invalid public configuration and foreign recovery scope fail preflight; this does not migrate existing intent or bypass recovery reconciliation.

Remaining work: administrative attempts/results, coordinated action/control journal and receipt gating, complete fenced reconstruction, external execution fencing, independent hosting/custody, secrets/Keycloak restoration and hosted/operator acceptance. No public or private-owner RPC, schema migration, deletion or cloud deployment is introduced here.
