# Reconcile persisted actions before recovery or use

The production objective requires recovery without lost acknowledged actions or replayed effects. Before implementing action exports, verify that each stored action agrees with its transition audit. Current row-level canonical/digest checks do not establish this relationship. This local repair is a prerequisite, not independent recovery or zero-RPO certification.

Keep the existing SQLite schema, action semantics, expiry behavior and public/private interfaces. Validate every persisted action on adapter construction, with bounded keyset pages; reject orphan audit rows and incorrect metadata counts. Before reading or changing an existing action, validate its bounded audit (at most four events in the current transition graph). Inside a mutation, write the action and corresponding audit atomically, then reconcile the resulting pair before sync/ack. Any integrity/storage error quarantines that adapter; no automatic repair or effect retry.

Expected histories: proposed; proposed→approved/rejected/revoked; proposed→approved→revoked/claimed; proposed→approved→claimed→succeeded/failed/indeterminate. The final state and row version must match history. All events bind to the action identity/digest, have positive increasing safe-integer sequences and nonnegative safe-integer timestamps. Do not require wall-clock timestamps to be monotonic: the existing writer uses the system clock. Proposed and claimed actors must match the original requester; approval/rejection actor matches the persisted grant, with distinct requester subject and entity. Revocation actor is a valid bounded principal summary, but cannot be reauthorized against today's policy. Completion actor must be exactly the internal execution worker and persisted claim ID. Reject noncanonical/extra actor data. Existing row validation continues to bind canonical action/grant/result data and expiry.

Checks cannot detect a privileged wholesale rewrite, a consistent rollback, or authenticate historical authorization against unavailable old policy. No additional assertion of such guarantees. Avoid loading all action payloads into memory; one row and at most five audit rows (extra sentinel) suffice, with key pages bounded to 128. Max10000 actions remains unchanged; startup scan cost must be measured in hosted acceptance.

Tests use native workerd SQLite and existing test-only SQL/read-fault controls. Cover corrupted audit, incomplete mutations, orphan records, recovery/reopen, late corruption across async authorization, failed insert/transaction rollback, legitimate complete/unfinished histories, no effect after quarantine and pages beyond128 keys. All public operations and internal completion share the validation boundary.
