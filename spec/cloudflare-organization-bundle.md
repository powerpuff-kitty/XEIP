# Complete organization recovery bundle

Status: local collector/offline verification complete; scoped review passed. The existing coordinated checkpoint supplies one initialized source view; this increment must collect all of its data into a complete offline-verifiable artifact.

The collector accepts the expected organization, a private destination that must not exist, and injected checkpoint/page readers. It captures and validates one coordinated checkpoint, then streams every action at its fixed audit cut, authority history from revision zero and administrative history from sequence one. Existing validators check complete chains and attempt/result relationships. Actions additionally require every audit sequence through the cut exactly once. Responses must identify the exact manifest and requested section. No retry, source write, journal append, deletion, command replay or activation occurs.

Files use mode 0600 inside a 0700 directory. Lifecycle, trust, authority and administrative checkpoint bodies remain separate, preserving their original byte/node budgets. Action records and bounded control pages have deterministic section-prefixed filenames. Every file is synchronized; a small final manifest binds the checkpoint and ordered file hashes and is written last, followed by directory/parent synchronization. An incomplete or uncertain collection throws and is not returned as a completed bundle; partial files remain for investigation and cannot be overwritten by retry. Local elapsed deadlines cover reader completion and validation, including synchronous work that crosses the deadline. No timeout permits late asynchronous continuation to seal the destination.

Offline verification checks protected regular files, strict canonical UTF-8 JSON, exact directory inventory, all component digests and cross-component configuration, complete action/authority/admin histories and the ordered file checksum. Expected organization is required. A caller can pin an independently retained checkpoint digest; a mismatch rejects an otherwise internally consistent artifact. Without such a witness, hashes establish content consistency only, not source authenticity, freshness, historical synchronization or an independent disaster boundary. Neither mode proves protection for acknowledgements newer than the cut. A chain across successive organization bundles remains separate from single-bundle content verification.

Implementation sequence: failing source-to-bundle and malformed/incomplete-file tests; shared verifier/file-reader reuse without changing existing formats; complete collector/offline verification and strict types; native lifecycle integration preserving a consumed claim and later action completion; failure/limit tests; affected and full regression, pinned Linux verification and one scoped review. Backout removes the new internal collector and its tests; no database or deployed artifact migration is involved.

Required acceptance: round trip and expected-digest pin; foreign/mixed checkpoint and page rejection; missing/extra/reordered/corrupt pages; empty histories and page boundaries; source advancement without changing the captured cut; protected files and refusal of symlinks/noncanonical JSON; fsync/write/reader/timeout failures without successful collection acknowledgement; valid bodies beyond generic JSON node limits; all source evidence untouched. Complete restore, current-journal reconciliation, external execution fencing, independent receipt gating, retention and hosted workload/security/operator acceptance remain open.
