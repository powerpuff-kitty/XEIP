# Organization staging artifact

Prepare an unpublished Linux/amd64 artifact for the approved single-organization direct-TLS runtime. The Linux route remains available; no reserved host exists, and Cloudflare-native exploration has not established a production hosting choice. This build enables staging; it does not close human workflow, retention, recovery, security or release acceptance gates.

Use the already tested, digest-pinned Node 22.23.3 Alpine base. Apply the signed Alpine `zlib=1.3.2-r1`, `libcrypto3=3.5.9-r0` and `libssl3=3.5.9-r0` security revisions in a shared base inherited by build, assembly and runtime; an unavailable exact revision fails the build. The actual-image smoke check verifies these installed revisions and the removal of global npm, Yarn and Corepack from the runtime. Build/assembly tooling remains available. Node independently bundles OpenSSL 3.5.8; the Alpine upgrade does not fix that copy. BusyBox and bundled-library findings remain open. See the [package assessment](audits/2026-10-11-linux-image-vulnerabilities.md) for the advisory and evidence. A multi-stage build installs the exact npm lockfile without lifecycle scripts, compiles the TypeScript SDK and the fixed browser console bundle, and installs only production dependencies in a separate stage. The runtime receives an explicit list of application modules, shared identity helpers, compiled SDK, immutable SQL migrations, console assets with checksums and third-party license inventory, license and dependency manifests. It excludes repository history, tests, fixture keys, operator configuration, build tools and development dependencies. Run as UID/GID 1000; all application files are root-owned and read-only to that user. Only the separately mounted trust state is writable. Operator secrets/configuration are mounted read-only with the protection required by the loader. No embedded credentials or automatic migrations.

Generate a CycloneDX npm dependency SBOM and SHA-256 file manifest from the assembled artifact. This is an unsigned dependency inventory, not OS-package attestation or security certification. The base image digest records the OS/runtime input. The uncommitted working tree must be described as an experimental local build, never attributed solely to HEAD as if clean. Publication, version tagging and signed provenance remain gated on a reviewed clean commit.

Verify actual build output: non-root identity, CLI dependency/migration loading, rejected incomplete configuration, absence of development tools and fixture/private material, and manifest integrity. Run with no network, read-only filesystem, dropped capabilities and no-new-privileges for smoke checks. Document separate migrations, TLS/secret/state mounts, shutdown time, readiness, upgrade/rollback and reserved-host acceptance requirements. A container smoke check is not an end-to-end deployment or workload result.

## Repeatable image vulnerability gate

After the build and artifact smoke, the `organization-artifact` CI job runs:

```sh
bash conformance/organization-image-scan.sh xeip-organization:local-review /tmp/xeip-image-scan
```

The report directory must not exist. The command inspects the local Linux/amd64 image, saves that exact image ID, hashes the archive and scans its final filesystem with digest-pinned Grype. The advisory database is prepared in a separate container with network access but no image, source or credentials mounted. The scan runs offline, non-root and read-only, with database age/hash checks enabled. Scanner errors, missing/invalid reports, unknown severities and High/Critical matches fail the command. A lower-severity result remains visible and does not imply security acceptance.

Reports retain vulnerability matches, database identity, scanner logs, sanitized image digests, the exported archive hash and separate scanner/command exits. Grype's encoded image configuration and manifest are removed from retained JSON. Raw JSON and the image archive live only in owned temporary storage and are removed on exit. Failed or malformed scans retain available diagnostics; malformed raw output is not uploaded. There is no Docker socket or source mount inside the scanner. The CI upload step preserves available JSON/log/text evidence after success or failure for 14 days; it never selects the image archive or advisory cache. This CI evidence lifetime is unrelated to organization action retention. A hard runner termination can still prevent cleanup/upload; inspect the failed job rather than interpreting missing evidence as success.

For repeated local runs, `XEIP_GRYPE_DB_VOLUME` may name an existing Docker volume containing only the public Grype database. It is checked for updates and validated on every scan; the command never deletes this supplied volume. Without that variable, the command creates and removes its own cache. Cache initialization uses a separately pulled, digest-pinned Node base with no network or application code. Do not place credentials or private data in the public cache. Updating scanner/helper pins requires review and revalidation.

The command's High/Critical threshold is a regression check, not the complete release policy. The [image assessment](audits/2026-10-11-linux-image-vulnerabilities.md) still records open BusyBox and bundled-library risks. Build-stage tools, removed files in inherited layers, signed provenance and actual hosted CI/release acceptance remain separate work.

The uploader is pinned to [actions/upload-artifact v7.0.2](https://github.com/actions/upload-artifact/releases/tag/v7.0.2), commit `cf430e030ddbb5b0abf93d22962f4752f3646cd9`. Its [action definition](https://github.com/actions/upload-artifact/blob/cf430e030ddbb5b0abf93d22962f4752f3646cd9/action.yml) uses Node 24 and preserves the archive, retention and missing-file inputs used here. This is the GitHub action's runtime; the application image remains Node 22. GitHub Enterprise Server is outside this workflow's verified scope.
