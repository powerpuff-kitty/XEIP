# Private organization export: capture cost

Status: optimized capture-only probes complete locally at100000 administrative records, but the first complete private bundle run at that size times out during capture. Complete collection and offline verification pass at1000 and10000 records. Maximum full-bundle and combined-resource acceptance remain open; production readiness remains no-go. These are local measurements, not hosted latency or memory certification.

## Scope and reproduction

Run each size in a fresh process:

```sh
node --expose-gc conformance/organization-cloudflare-export-cost.mjs 1000
node --expose-gc conformance/organization-cloudflare-export-cost.mjs 10000
node --expose-gc conformance/organization-cloudflare-export-cost.mjs 100000
```

The diagnostic uses the actual `OrganizationService`, schema, checkpoints and export session with Node SQLite in memory. It initializes a small synthetic organization, closes the service, seeds a valid immutable administrative chain, reopens, captures and checks the complete head, then attempts export begin and a first component read. Nested transactions use SQLite savepoints. It refuses outbound fetches and asserts none occurred. It never deploys, uses real credentials, performs an MCP effect or accesses an existing database.

The measured host is macOS x64, Node v26.8.1, shared and contended. Data has zero actions, empty active trust and a small fixed authority/lifecycle configuration. Disk synchronization is a no-op in this adapter; network, complete bundle transfer, file writes, reconstruction and maximum combined component size are excluded. Timings begin after data seeding. Source-open cost is reported separately from subsequent operations. Memory fields describe the whole Node process, including SQLite and diagnostic fixture state; cumulative peak RSS also includes setup. They are not workerd isolate memory measurements.
