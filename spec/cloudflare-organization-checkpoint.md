# Coordinated organization recovery capture

Status: local implementation verified; scoped review correction complete. This connects the existing control checkpoints and fixed-cut action evidence; independent receipt gating and complete reconstruction remain required.

`OrganizationService.recoveryCheckpoint()` captures an initialized organization only. It conflicts with pending initialization, owner administration, trust refresh or another control capture. Under the control guard it synchronously captures lifecycle, signed trust, authority, administrative head and the current action snapshot. It then synchronizes local storage and rechecks the same control state and historical action cut. Storage or integrity failure quarantines the service; ordinary pending recovery admission conflicts without poisoning healthy state. Close during capture cannot return success.

The coordinator retains only the first capture's independently copied, recursively frozen manifest across synchronization. Its action cut constrains the second read, and its digest must exactly match the second manifest. The first component graph is no longer needed and may be collected before the second is built. Both complete reads and all validation remain required; this lifetime reduction does not guarantee collection timing or a hosted memory budget. Verification for this refinement is recorded in the [export plan](plans/cloudflare-organization-export.md).

Public actions may progress during synchronization. Their audit history reconstructs exactly the earlier cut, including consumed claims with an unknown external outcome. The capture must not revoke a legitimate in-flight action merely to obtain a backup. A newly busy action recovery adapter can require retrying capture. Later acknowledgments require later journal reconciliation before restoration can activate; this API alone cannot meet no-loss recovery.

The result contains separate `manifest`, `lifecycle`, `trust`, `authority` and `administration` records. Manifest `xeip.organization-checkpoint/1` binds organization, all four component digests, an action snapshot (cut/count/digest), and its own digest. The trust artifact is hashed in full with a new domain, because its source checksum alone does not bind organization. Existing component formats and checksums remain unchanged. Bodies retain their existing independent size/node limits; no new all-components parser cap may reject valid source bodies. No credentials are included.

Offline validation requires every component's expected organization, complete checksum/digest validation and cross-component agreement: initialized lifecycle, normalized trust configuration, unchanged provider identity fields, current authority targets within the pinned runtime targets, and exact revision-zero authority equal to initial intent. Manifest digests must match the validated bodies. Hashes do not authenticate provenance or establish freshness against replacement-history rollback.

`recoveryPage(manifest, {section, cursor})` reads bounded internal action, authority or administration evidence. Actions use their historical cut and exclusive proposal cursor; authority/admin pages require their current checkpoint digest to match the manifest and use the existing predecessor/limit cursors. Each result binds the manifest digest and section. Invalid input does not quarantine healthy state; detected storage corruption does. A bounded page read is not a complete integrity attestation of every unselected record. Public HTTP and private owner commands gain no new route. The [complete bundle collector](cloudflare-organization-bundle.md) uses complete-history validators to verify every page through the pinned component heads; a manifest alone does not prove complete exported data.

A missing nonzero action cut triggers ledger reconciliation before returning `StoreConflict`. This distinguishes a caller requesting a nonexistent position in intact history from storage corruption that deleted a previously captured event. The latter quarantines the ledger/service and prevents subsequent tool execution. Numeric input validation still occurs before storage work. Successful page reads retain their existing bounded behavior; the missing-cut error path and checkpoint capture can scan complete retained history. Local correctness tests do not certify capture duration, maximum-size CPU/memory or the hosted P95 target.

Standalone lifecycle checkpoints continue to preserve interrupted setup. This initialized capture does not fabricate missing trust/authority for partial initialization. Partial-setup journal recovery, durable receipt gating, coordinated source reconciliation, complete fenced reconstruction and execution fencing remain separate requirements, along with accepted independent hosting/custody, retention, real Keycloak/MCP, workload/security/operator acceptance. No schema migration, journal-format change, deployment, deletion or activation is included.

Verification: native workerd/SQLite exact capture and page round-trip; control conflicts; action completion during held sync preserving an earlier consumed/pending cut; corruption/closure/sync refusal; malformed/scope/mixed-component artifacts; later authority/admin updates; full local regression and affected pinned Linux/types; scoped review. Existing action recovery sequencing must remain unchanged.
