## Outcome and constraints

An operator uses the existing explicitly local or remote owner binding to collect one complete organization bundle into a new private directory. The resulting files must pass the existing offline verifier and feed the existing fenced reconstruction library without changing either format. Console output contains bounded identifiers and counts, never checkpoint bodies, credentials or unexpected remote fields. No public HTTP administrator route, organization initialization, restore activation, deployment or deletion is introduced.

At the start of this task, the collector accepted injected internal readers and owner RPC supported only action snapshots/pages and administrative audit pages. A trust checkpoint can occupy16MiB, lifecycle approximately2MiB and authority approximately1MiB; sending the complete checkpoint as one owner receipt would exceed the existing response boundary. The original control-history readers also required the current head, so normal administration could invalidate a long-running bundle collection. Both issues belong to this change.

## Chosen contract

Keep the existing owner identity from binding properties and exact request/response correlation. Add private export begin, component-part, history-page and close operations. Begin captures the existing synchronized organization checkpoint and returns an opaque export UUID, checkpoint manifest and four component descriptors containing canonical byte length, SHA256 and part count. It never returns complete large components.

Retain at most one export session per source instance, bound to its originating operator. Store canonical component bytes and the checkpoint context needed for history reads; release redundant object copies after capture. Fix component names to lifecycle, trust, authority and administration. Use canonical JSON plus the same trailing newline as bundle files. Each part carries at most262144 decoded bytes as canonical base64; the complete correlated response stays below524288 bytes. Neither arbitrary paths nor caller-selected byte limits are accepted. Component descriptors remain subject to their existing independent byte and node budgets.

Use a30-second idle expiry renewed only by a successfully validated read and a one-hour absolute lifetime. A new begin conflicts while a live session occupies the slot. Explicit close releases only the matching operator/session. Expiration, source restart, source close/failure or lost state makes the old session unavailable; callers start a new collection in a new directory. No partial bundle is silently adopted. Reads have deadlines and late responses cannot seal collection or revive a closed session. No automatic retries are needed to achieve correctness.

History pages use the captured action cut, authority checkpoint and administrative checkpoint. Actions already support historical cuts. Add explicit internal historical authority/admin readers while preserving existing current-head APIs. Before reading a historical page, validate current source integrity, require the captured head to exist in retained history, and compare its exact checksum and relevant configuration digest/predecessor. Bound SQL to the captured revision/sequence, validate cursor predecessor and validate the resulting page with the existing checkpoint validators. Missing/corrupt retained source history quarantines the source; a foreign or otherwise unmatched caller checkpoint cannot alter healthy state. A captured empty administrative head remains empty after later events. Later authority changes, completed administrative attempts and trust refreshes must not leak into the captured bundle.

The source session is ephemeral read state, not durable backup evidence or permission to execute. The operator still needs a separately trusted checkpoint digest and independent custody for stronger authenticity/rollback guarantees. This task does not cover acknowledgements after the captured cut, control receipt gating, external execution fencing or Keycloak/secrets/MCP recovery.
