## Interfaces and constraints

Client: accepts fixed origin/gateway, bound principal/device signing key, an asynchronous in-memory token supplier and standard fetch. Exposes inspect, explicit decide and revoke. Only client-issued immutable reviews authorize decisions. Token supplier executes before building the signed deadline; network responses never replace the reviewed digest silently.

Device store: issuer+subject namespace, generated Ed25519 CryptoKey with non-extractable private part, atomic IndexedDB creation, public key ID only in enrollment output. No automatic replacement of corrupt/lost enrolled keys.

Server: optional console public client ID; static public bootstrap plus authenticated profile are separate from signed `/v1/actions`. Profile does not enroll or authorize an action. All network work is bounded and observed under the existing request lifecycle.

Build: pin keycloak-js and browser/bundling tools, include their inventory/licenses and actual built assets in the artifact. The container must remain non-root/read-only and console assets must be fixed at startup.

Review focus: account/device substitution after asynchronous login or token refresh; digest/action changes between review and decision; duplicate effects or decisions after network ambiguity; browser key persistence/XSS and secret leakage; bypasses introduced by new profile/static routes.
