# Experimental organization authority

`DurableOrganizationAuthority` composes the existing Keycloak JWT/JWKS/introspection verifier, action policy and persistent signed trust. It is an internal object-owned component. It is not a public administration API or deployable Worker service.

Use one authority, one trust adapter and one shared ledger per live organization object. Open verified trust first, then call `DurableOrganizationAuthority.open(storage, {organization, trust, introspectionClientSecret, initialize})`. Obtain the credential from a runtime secret binding; never put it in the public configuration. Supply `initialize` only on explicit first creation. It contains `{authentication, policy}` using the existing Keycloak and action-policy configuration contracts, with `introspectionClientSecret` omitted. Ordinary reopen reads and validates the existing snapshot; it cannot reset missing or corrupt state. Issuer, API audience and introspection client ID are immutable after initialization.

The checked version-3 schema adds an authority snapshot and append-only revision/checksum events. Each configuration write and its event commit together. Each event binds the configuration digest and previous event checksum; the snapshot anchors the latest checksum. Reopen and update validate canonical configuration and the entire chain in 256-row batches, including historical events. No bearer, client secret or private signing key is stored. Checksums do not protect against a malicious database owner rewriting all state.

Owner-only `update(configuration, {expectedRevision})` is a complete replacement. Invalid input or a stale expected revision preserves current authority. Starting persistence gates authentication and eligibility; the replacement activates only after storage synchronization. Concurrent updates conflict. A SQL/sync error or timeout disables the instance until validated reopen. `close()` prevents late activation. Secret rotation requires a new instance with the new runtime credential; there is no secret-writing API.

`authenticate`, `revalidate` and `release` implement the shared authentication contract. Only the exact issued principal can revalidate. Provider, binding, policy or trust changes invalidate pending requests; a per-instance nonce also prevents a same-version reopen from reviving a ticket. Request cleanup must always call `release`, including denied/aborted requests. Persisted approval consent continues to use current binding/trust/policy checks rather than requiring the approver's old bearer; explicit action revocation permanently prevents that action from executing, while key eligibility follows current signed trust. Re-adding previously removed membership is an explicit operator decision.

Use `ledger.withAuthorization(requestGuard)` to narrow the shared ledger for the signed controller's request-specific checks. Facades retain the original ledger's fault quarantine. The base authority always runs, and a guard cannot grant permission the base authority denies. Construct the executor with the current `authority.policy()` when each execution begins so fresh actions after a legitimate update use the new policy. At the connector's final pre-send boundary, combine the controller's live request guard with `authority.authorize(principal, context)` so current policy and approver eligibility are checked even if the executor captured an older policy object. Internal `finish` remains usable after caller authority disappears; it never authorizes a retry of the effect.

Run `npm run test:cloudflare` and `npm run typecheck:cloudflare`. These use actual workerd/SQLite, signed provisioning and RS256 tokens, with controlled network issuer responses and fake effect counters. `npm run test:cloudflare:keycloak` separately starts the pinned disposable Keycloak fixture and exercises the same adapter through real provider endpoints. It requires Docker. Its approver uses a fixture service account, so it does not certify browser/PKCE login. Never deploy either privileged conformance worker.

Limits include the shared JSON structural bounds (8192 nodes, depth 32), a 1 MiB public snapshot cap, and existing policy/trust bounds. These are safeguards, not capacity measurements. Event retention, administrative actor attribution/export, hosted restore fencing, supported time assumptions and capacity acceptance remain open. Full signed Worker HTTP ingress, private MCP transport, deployed identity/secret/network operations and human login acceptance are still required. No Cloudflare account or deployment is created by these tests.

For internal fixed-cut export, `historyPageAt(checkpoint, cursor)` can read an earlier captured authority head after later updates. It validates current source integrity, matches the retained head's configuration digest, predecessor and checksum, and bounds every page to that captured revision. It does not reconstruct old configuration bodies or activate old authority. The existing `historyPage` still requires the current head. Both paths retain full source-history validation, so maximum-history export cost remains unverified. Private operator transport is still being implemented in the [complete export plan](../../../spec/plans/cloudflare-organization-export.md).

See the [spec](../../../spec/cloudflare-authority.md), [evidence and decisions](../../../spec/plans/cloudflare-authority.md), [trust lifecycle](TRUST.md) and [production gates](../../../PRODUCTION_READINESS.md).

`historyReaderAt(checkpoint)` verifies the complete retained history and captured head once, then provides `page(cursor)` and `close()` for an internal export. Each page checks schema, scope, the live instance's accepted state and tail, the captured anchor, predecessor and selected records. Legitimate later updates may advance the live head without entering the export. Out-of-band heads, changed verified anchors and damaged selected records fail closed. Malformed caller cursors preserve healthy state. Closing the authority or reader permanently disables that reader. This attests selected history; the collector must verify every page through the captured head before sealing a bundle. Standalone page APIs and live mutation checks retain their full scans.

`captureHistoryReader()` captures the fully verified current checkpoint and a scoped reader in the same synchronous pass. It accepts no external checkpoint or verification proof. Organization export uses this factory during its confirmed post-sync capture, retaining the full pre/post manifest comparison while avoiding a third complete history scan. The checkpoint is immutable, and callers must close the reader on completion or failure. This internal method adds no durability receipt or activation permission.
