# Experimental Worker transport

The Fetch adapter and shared MCP connector run in local workerd. This transport is included in the experimental [Worker package](WORKER.md). No Cloudflare account or resources have been created.

`createWorkerHttp({controller, origin, ready, ...limits})` returns a Fetch handler. Instantiate it once per live organization object so admission counts span requests. Supply the already-initialized signed `OrganizationController`, an exact HTTPS origin and a bounded readiness callback. Call it with `{waitUntil: task => ctx.waitUntil(task)}` to keep completion work attached to the request lifetime. Never recreate the handler, authority or ledger for every request: doing so resets admission or fault quarantine.

Only `POST /v1/actions`, `GET /live` and `GET /ready` are served. Origin/Host checks, JSON media type, UTF-8, declared and streamed size, body deadlines, response size and operation deadlines are bounded. Errors use a fixed allowlist; responses are uncached and contain generated request IDs. No forwarded or Cloudflare identity header establishes XEIP identity. The controller still verifies the bearer, signed envelope, exact organization/session and current authorization. Fetch normalizes some headers; raw edge-header behavior must be checked in hosted staging.

A timeout aborts the operation signal and returns an error. Unfinished work retains its admission slot until it settles, including after client cancellation. Liveness remains reachable during saturation; readiness shares admission. Background completion is not a recovery guarantee: a consumed durable claim, an indeterminate outcome and refusal to replay remain the crash boundary.

The MCP adapter uses the existing official SDK and exact configured target, recipient, revision, tool, resource, issuer, token endpoint and OAuth scope. It refuses redirects before following any Location, checks current authorization immediately before the tool request and never retries an uncertain effect. Do not put user bearer tokens into connector configuration. Each target has separate configured credentials. Production endpoints require HTTPS; literal-loopback HTTP exists solely for conformance fixtures.

Run `npm run test:cloudflare` and `npm run typecheck:cloudflare`. The transport fixture uses a real independent MCP SDK server and controlled RSA/JWKS/introspection provider. It verifies signed propose/approve/execute/inspect, revocation during OAuth, uncertain outcomes, restart without replay and public routing without privileged fixture controls. Real Keycloak protocol evidence remains in the separate `npm run test:cloudflare:keycloak` fixture. These runs do not test a person logging in through a browser or a real organization's private network.

Never deploy `conformance/organization-cloudflare-*-worker.mjs`: private fixture interfaces intentionally permit initialization, SQL and fault manipulation. The [Worker package](WORKER.md) implements private owner initialization, strict secret/binding configuration, lifecycle/readiness, administrative audit and optional [automatic signed refresh](REFRESH.md). Ordinary traffic must never create missing trust or authority state. Real private MCP connectivity, retention, independent recovery fencing and acknowledgment reconciliation, hosted recovery/load tests and operator/security acceptance remain open. Requirements remain 500 users, 200 agents, 120 actions/minute, P95 machine operations ≤2 seconds, restore ≤1 hour and no acknowledged-action loss.
